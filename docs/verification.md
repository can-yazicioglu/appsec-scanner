# Verification record

Results below are observations from this workspace, not promises of complete
vulnerability coverage. Deliberately vulnerable fixtures contain synthetic data.

## v0.1 checkpoint — 2026-09-24

Installed editable package with dev/browser extras in `.venv`, then installed
Playwright Chromium. `pytest -q -m 'not browser'`: **29 passed**, 3 deselected.
`pytest tests/test_browser.py -q`: **3 passed** using real headless Chromium.

Verified static links/forms, manual CLI scan plus export, persistence after
reopening SQLite, finding deduplication/normalization, redaction, repeated real
SQLite boolean proof, reflection/error-only suspected classification, rejection
of variable SQL responses, matching browser XSS execution, rejection of
unrelated alerts, SPA fetch discovery, off-allowlist HTTP redirects, browser
redirects and browser fetch blocking. A request-budget failure is recorded as
failed/partial, never a clean result.

`python -m examples.generate_samples` generates `sample-fixture-dast.json`
against the running local fixture; it is **not a Juice Shop scan**. Dynamic
loopback ports and IDs/timestamps are generated by the actual run.

Docker is unavailable in this environment, so Juice Shop Docker startup and the
scanner Docker build are unverified. Juice Shop **v19.2.1** source inspected:
`routes/search.ts` interpolates `q` into a nested SQL LIKE expression, so generic
boolean payloads may not balance its parentheses; an error indicator may be the
only supported result. API reflection cannot demonstrate browser DOM XSS.
Do not infer target findings from fixture results.

alternatives and identity verification passed against the live fixture.
